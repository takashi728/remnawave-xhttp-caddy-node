# Remnawave Node & Caddy Deployment

Deployment bundle for Remnawave nodes on Ubuntu 22.04+, Debian 11+ (amd64/arm64), and Arch Linux, using Caddy for TLS/ACME and Element Web as a local cover site.

## Requirements

- Ubuntu 22.04+, Debian 11+, or Arch Linux (amd64 or arm64)
- Root or `sudo` access
- A domain with an A/AAAA record pointing to the VPS
- A Remnawave node `SECRET_KEY` from your panel

## Installation

Clone the repo and run the installer:

```bash
git clone https://github.com/takashi728/remnawave-xhttp-caddy-node.git
cd remnawave-xhttp-caddy-node
sudo bash setup-scripts/install-node-caddy.sh
```

On Arch Linux:

```bash
sudo bash setup-scripts/install-node-caddy-arch.sh
```

The installer will ask for:

- Email address for Let's Encrypt
- Node domain (e.g. `node.example.com`)
- Optional extra inbound TCP ports or ranges (comma-separated)
- Remnawave `SECRET_KEY`
- Whether to enable Node API SNI verification (`y/N`, requires panel support)
- XHTTP path (auto-generated by default)

On Debian and Ubuntu, the installer also prepares the latest available distro kernel (without rebooting automatically). Reboot after install if a newer kernel was installed, or skip that step with:

```bash
sudo SKIP_KERNEL_UPDATE=1 bash setup-scripts/install-node-caddy.sh
```

All runtime files are placed under `/opt/remnanode`.

## Panel Profiles & Web Mode

After installation, add the node in your Remnawave panel and pick a profile from `panel-profiles/`.

### Recommended: XHTTP over Caddy Unix Socket

- **Obfuscated profile:** `panel-profiles/vless-xhttp-caddy-socket-obfs.json` with client XHTTP extra settings from `host-overrides/xhttp-obfs-xmux.json` (leave general outbound MUX unset)
- **Standard profile:** `panel-profiles/vless-xhttp-caddy-socket-selfsteal.json`

Host settings in the panel:

- **Address:** your node domain
- **Port:** `443`
- **Security Layer:** `TLS` (do not leave on inherited `none`)
- **SNI:** your node domain
- **ALPN:** `h2`
- **Fingerprint:** `chrome`
- **Path:** the `XHTTP_PATH` printed by the installer (or shown by `node-status.sh`)

Then enable Caddy socket mode on the node:

```bash
sudo /opt/remnanode/enable-xhttp-socket-caddy.sh
```

### Optional: XTLS-Vision

- `panel-profiles/vless-xtls-vision-tls-selfsteal-no-fallback.json`
- `panel-profiles/vless-xtls-vision-tls-selfsteal-fallback.json`

Set the flow to `xtls-rprx-vision`. If you use the fallback profile, enable the local cover site:

```bash
sudo /opt/remnanode/enable-vision-fallback-caddy.sh
```

> [!NOTE]
> Use either XHTTP socket mode or Vision fallback mode on a node, not both at once.

`panel-profiles/` also contains experimental test and bridge profiles (`xhttp-obfs-test.json`, `bridge-a-transit-xhttp-obfs-to-b-vision.json`, `bridge-b-dest-xtls-vision.json`).

## Maintenance

Check node status, paths, certificates, and running services:

```bash
sudo /opt/remnanode/node-status.sh
```

Apply optional TCP/network tuning:

```bash
sudo /opt/remnanode/enable-network-tuning.sh
```

Check containers and logs:

```bash
docker ps
docker logs remnanode --tail=100
```

Certificate renewal runs automatically via cron (`/etc/cron.d/remnawave-caddy-cert-export`).

To customize ports or node options (`NODE_PORT`, `SNI_VERIFICATION`, `CUSTOM_CORE_URL`), edit `/opt/remnanode/.env` and recreate the stack. Container image versions are pinned in `docker/docker-compose.yml`.

Uninstall the stack (add `PURGE_DATA=1` to also remove certs, `.env`, and Caddy data):

```bash
sudo /opt/remnanode/uninstall-node.sh
sudo PURGE_DATA=1 /opt/remnanode/uninstall-node.sh
```
